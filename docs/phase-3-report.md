# SkillSeat Phase 3 consolidated report

1. **Status:** Phase 3 is complete within its documented development scope, including genuine hosted Stripe sandbox payment and signed webhook verification on 18 October 2026. Phase 4 has not begun.
2. **Features:** public discovery/details, registration/account editing/password changes, owner studio/publication, booking/cancellation/expiry, Stripe test Checkout/webhooks, private resources and eligible reviews. [Acceptance map](phase-3-architecture.md#acceptance-evidence-map).
3. **Architecture:** established custom User plus Workshop, Booking, PaymentAttempt, PaymentEvent, Resource and Review in one domain app. Integer GBP pence, aware UTC dates, explicit constraints, partial active-booking uniqueness and durable event receipts. [Full model/state design](phase-3-architecture.md).
4. **Authentication/roles:** Django validators, hashed passwords, safe redirects, own-profile forms and session-preserving password changes; administrators grant add_workshop, registration cannot self-promote. Superusers manage across owners. No user model replacement.
5. **Workshops:** public upcoming published listings; published historical details retain reviews without advertising seats. Owner-scoped create/edit/publish/unpublish, booking roster, attendance and conditional capacity edits; forged owner IDs excluded.
6. **Booking:** free reservations confirm immediately; paid reservations hold one place for 35 minutes. Duplicate active bookings rejected. Own cancellation before start and executable expiry each release exactly once. Terminal bookings never silently reactivate.
7. **Concurrency:** seven barrier-synchronised independent-connection races pass on shared-memory and file-backed SQLite. Final-seat, duplicate reservation, cancellation, expiry, capacity reduction, duplicate payment and payment/cancellation cases are covered. [File-backed output](testing/phase3-file-concurrency.txt). PostgreSQL remains untested.
8. **Stripe:** SDK 16.0.0 / API 2026-09-30.endive. The replacement restricted test key passed application Checkout creation/retrieval and authenticated CLI forwarding. A fresh £25 GBP Session was verified test/open/unpaid, then paid manually by the user in Edge without browser automation. Actual signed checkout.session.completed delivery returned HTTP 200 and confirmed the paid booking/succeeded attempt at one reserved seat. Paid resource download returned exact bytes; invalid signatures and body tampering returned 400; two genuine-body/signature replays returned 200 without duplicate receipts or capacity changes. [Actual provider evidence](phase-3-evidence.md#completed-manual-sandbox-payment--18-october-2026).
9. **Resources:** 5 MB uploads into private storage, randomised names, no public media URL, owner-scoped management and authorised attachment responses. Paid+confirmed booking required for attendees; terminal/unpaid/unrelated/anonymous requests denied. Real file delivery/deletion is tested.
10. **Reviews:** confirmed booking + workshop ended + owner-recorded attendance, rating 1–5 and trimmed 10–2000-character body; one own review per workshop, own edit/delete, superuser visibility moderation. Hidden reviews stay hidden on edits.
11. **Interface:** responsive cream/teal visual identity, CSS ticket illustration, semantic shared forms, attendee dashboard and owner studio. [Before-implementation wireframes](design/phase-3-wireframes.md) and [real captures/comparison](design/phase-3-verification.md) are separate.
